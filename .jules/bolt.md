## 2024-05-26 - Markdown File Caching Impact in SSG
**Learning:** During Static Site Generation (SSG) in Next.js, using `generateStaticParams` and `generateMetadata` alongside the page content rendering leads to the same Markdown files being read from disk and parsed synchronously multiple times. `fs.readFileSync` combined with `gray-matter` parsing is surprisingly expensive (~1ms per call) and lacks built-in React `cache` support outside the App Router data fetching boundaries unless explicitly requested. However, using a global JS `Map` object for caching causes stale reads during local development and completely breaks Incremental Static Regeneration (ISR).
**Action:** Always wrap data-fetching functions like `getPostBySlug` with React's `cache()` function instead of using module-level state variables. This achieves the performance benefits of memoization without breaking hot-reloading or ISR updates. Cache reduced read times from ~1ms to ~0.015ms per call.
